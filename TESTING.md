# TESTING.md — руководство для тестировщика

Документ для разработчика, который видит проект впервые. В нём описано, как запустить каждую часть, что проверять, какой результат ожидается и где править код. Всё взято из кода репозитория (ноябрь 2026). Если что-то расходится с кодом, верен код. Если код расходится с `brief.md`, требованием считается `brief.md`.

## 2. Подготовка окружения

### Node.js

Проект использует Node.js из `~/.local/node`. На Mac владельца стоит v24, на Netlify используется Node 22 (`netlify.toml`). Перед любой командой:

```sh
export PATH=~/.local/node/bin:$PATH
cd <корень репозитория>
```

На своей машине достаточно любого Node.js 22 или новее: тестам нужны встроенные `node:test`, `fetch`, `Request` и `Response`.

### Зависимости

```sh
npm install
```

- `npm test` работает без установки зависимостей: тесты используют только встроенные модули Node.
- `@netlify/blobs` понадобится, чтобы запустить функции в Netlify Dev.
- Сейчас в `node_modules` на Mac владельца нет dev-зависимостей, поэтому `npm run typecheck` падает с `tsc: command not found`. Это касается только архивной Next.js-версии; после `npm install` команда найдёт `tsc`.

### Переменные окружения

Скопируйте `.env.example` в `.env`. Файл `.env` есть в `.gitignore`: **не коммитьте его и не вставляйте его содержимое в чаты и тикеты.**

| Переменная | Кто читает | Правило (из `netlify/functions/_shared/payment.mjs`) |
|---|---|---|
| `YOOKASSA_MODE` | функции оплаты | Должна быть ровно `test`, иначе оплата отключена |
| `YOOKASSA_SHOP_ID` | функции оплаты | Только цифры; shopId **тестового** магазина ЮKassa |
| `YOOKASSA_SECRET_KEY` | функции оплаты | Не пустой; секретный ключ тестового магазина |
| `YOOKASSA_ITEM_NAME` | `create-payment` | 1–128 символов без управляющих символов |
| `YOOKASSA_AMOUNT_KOPEKS` | `create-payment` | Целое число копеек от 1, до 12 цифр, без точки: `2500000` — это 25 000,00 ₽. **Не подставлять цену «от» с сайта** |
| `SITE_URL` | `create-payment` | Только origin, без пути и параметров. `https://…`, а для локальной проверки `http://localhost:8888` или `http://127.0.0.1:…` |
| `TELEGRAM_BOT_TOKEN` | `bot/bot.mjs`, `scripts/setup-telegram-bot.mjs` | Формат `цифры:строка из 30 и более символов`. Скрипты читают его из `.env` сами и не выводят в консоль |

На Netlify те же переменные задаются в настройках сайта, а не в файле.

## 3. Запуск

### 3.1. Сайт (`index.html`)

Откройте `index.html` двойным щелчком или в Chrome. Сервер не нужен, всё работает, **кроме оплаты**: функций рядом нет, и форма покажет ошибку сети.

Режимы для проверки:
- **Ночная тема:** переключатель в шапке. Выбор хранится в `localStorage`, ключ `theme` (`night` / `day`).
- **Без анимаций:** запустите Chrome с флагом `--force-prefers-reduced-motion`:
  ```sh
  open -na "Google Chrome" --args --force-prefers-reduced-motion --user-data-dir=/tmp/chrome-rm
  ```
- **Мобильная вёрстка:** DevTools → Toggle device toolbar.

### 3.2. Mini App (`tg-app/`)

- **В браузере на Mac:** откройте `tg-app/index.html`. Приложение работает и без интернета: шрифты и копия Telegram SDK лежат в папке. Вне Telegram нет имени пользователя и вибрации, кнопки «Назад» в шапке Telegram тоже нет.
- **На телефоне в той же Wi‑Fi сети:**
  ```sh
  cd tg-app && python3 -m http.server 8080 --bind 0.0.0.0
  ipconfig getifaddr en0          # IP Mac
  ```
  Затем откройте на телефоне `http://<IP>:8080/`.
- **Внутри Telegram:** опубликованная версия открывается кнопкой меню у бота @stvnislv_bot.

Параметры адреса для проверки (из `tg-app/app.js`):

| Адрес | Что делает |
|---|---|
| `index.html#services` (а также `#portfolio`, `#contact`) | Открыть сразу этот экран. В Telegram это делает `?startapp=services` |
| `?welcome=1` | Показывать окно «Привет» всегда |
| `?offer=1` | Показывать оффер всегда |
| `?lite=1` / `?lite=0` | Включить лёгкий режим / не включать его по замеру кадров |

Сбросить флаги «уже видел» в консоли: `localStorage.removeItem("welcomeSeen")` и `localStorage.removeItem("offerSeen")`.

### 3.3. Функции оплаты локально

Для них нужен Netlify Dev и тестовые переменные в `.env` (`SITE_URL=http://localhost:8888`). Владелец пользуется CLI версии **27.10.2**: в 27.16.2 падает `netlify login`.

```sh
npx netlify-cli@27.10.2 dev
```

> ⚠ В этой сессии локальный запуск Netlify Dev не проверялся. В `netlify.toml` нет раздела `[dev]`, поэтому CLI может спросить, как запускать проект, или сам определить Next.js по `package.json`. Если так и случилось, укажите статическую папку: `npx netlify-cli@27.10.2 dev --dir .`. Сайт должен открыться на `http://localhost:8888`.

Webhook от ЮKassa до `localhost` не дойдёт, поэтому статус заказа локально останется `pending`. Как сымитировать уведомление, написано в разделе 5.3.

### 3.4. Бот

```sh
node scripts/setup-telegram-bot.mjs --check   # только показать текущие описание, команды и кнопку меню
node scripts/setup-telegram-bot.mjs           # записать описание, короткое описание и команды из объекта BOT
node bot/bot.mjs                               # запустить бота; остановка — Ctrl+C
```

- Для обоих скриптов нужен доступ к `api.telegram.org`. Из России он может открываться только через VPN, при сбое скрипты так и пишут.
- `setup-telegram-bot.mjs` проверяет, что токен выдан именно для `@stvnislv_bot`. Если нет, он ничего не меняет.
- Второй экземпляр бота сразу завершится с сообщением «Этот бот уже запущен…» (ошибка 409 от Telegram).
- Если у бота включён вебхук, `bot.mjs` откажется запускаться и ничего не изменит.

### 5.2. Оплата в браузере (опубликованный сайт или Netlify Dev)

Форма находится в разделе «Услуги». Используйте только тестовый магазин и тестовые карты ЮKassa (номера карт — в документации ЮKassa).

| Шаг | Ожидаемый результат |
|---|---|
| Отправить пустую форму | Подсказки браузера «Укажите имя (не более 100 символов).» / «Укажите корректный адрес электронной почты.», запроса нет |
| Имя из одних пробелов | То же сообщение про имя (пробелы обрезаются) |
| Корректные имя и почта | Кнопка меняется на «Создаю платёж…» и блокируется, затем переход на страницу ЮKassa (`https:`) |
| Переменные не заданы или `YOOKASSA_MODE` не `test` | Под формой «Тестовая оплата пока не настроена.», кнопка снова активна |
| Оплатить тестовой картой и вернуться | Адрес `/?payment=<orderId>`, форма скрыта, текст «Платёж создан. Ждём подтверждение ЮKassa…», затем «Оплата подтверждена.» после webhook |
| Отменить платёж у ЮKassa | «Платёж отменён.», форма снова видна |
| Webhook не пришёл | Браузер опрашивает статус 60 раз каждые 3 с (около 3 минут), потом показывает «Подтверждение пока не получено. Обновите страницу позже, чтобы проверить статус.» |
| Открыть `/?payment=<чужой или выдуманный UUID>` | Сервер ответит 404, на странице «Ждём подтверждение ЮKassa. Статус обновится автоматически.» до конца опроса |

**Главное правило:** возврат браузера со страницы ЮKassa **не** считается оплатой. Статус `succeeded` ставит только `yookassa-webhook` после того, как сверит платёж через API ЮKassa.

### 5.3. Функции оплаты — контракт и проверки через curl

База: `https://stvnislv.netlify.app` или `http://localhost:8888`. Все ответы — JSON с заголовком `Cache-Control: no-store`.

#### `POST /.netlify/functions/create-payment`

Проверки идут в этом порядке: метод → настройки → `Origin` → тело.

| Условие | Код | Тело |
|---|---|---|
| Метод не POST | 405 | `{"error":"Метод не поддерживается."}` |
| Переменные не заданы или неверны | 503 | `{"error":"Тестовая оплата пока не настроена."}` |
| Заголовок `Origin` не равен `SITE_URL` | 403 | `{"error":"Запрос отклонён."}` |
| `Content-Type` не `application/json` | 400 | `Ожидается JSON.` |
| Тело больше 4096 байт | 400 | `Форма слишком большая.` |
| Битый JSON | 400 | `Некорректный JSON.` |
| Не объект / массив / `null` | 400 | `Проверьте имя и электронную почту.` |
| Поля, кроме `name` и `email` (например `amount`) | 400 | `Форма содержит неизвестные поля.` |
| Имя пустое, длиннее 100 символов или с управляющими символами | 400 | `Укажите имя длиной до 100 символов.` |
| Почта не по шаблону `x@y.z`, длиннее 254 символов | 400 | `Укажите корректную электронную почту.` |
| ЮKassa ответила ошибкой или не ответила за 10 с | 502 | `Не удалось создать платёж. Попробуйте позже.` (заказ → `failed`) |
| ЮKassa вернула `test` не `true`, нет `id` или ссылка не `https` | 502 | `Не удалось создать ссылку для оплаты.` (заказ → `failed`) |
| Успех | 200 | `{"orderId":"<uuid>","confirmationUrl":"https://…"}` (заказ → `pending`) |

Что важно проверить:
- Сумма берётся **только** из `YOOKASSA_AMOUNT_KOPEKS`. Клиент не может её передать: лишнее поле даёт 400.
- В ЮKassa уходят `capture: true`, `return_url = SITE_URL/?payment=<orderId>`, `description = YOOKASSA_ITEM_NAME`, а в `metadata` — `order_id`, `customer_name`, `customer_email`. `Idempotence-Key` равен `orderId`.

```sh
BASE=http://localhost:8888
# 403 — чужой Origin
curl -i -X POST $BASE/.netlify/functions/create-payment -H 'Origin: https://evil.example' -H 'Content-Type: application/json' -d '{"name":"Анна","email":"anna@example.com"}'
# 400 — лишнее поле amount
curl -i -X POST $BASE/.netlify/functions/create-payment -H "Origin: $BASE" -H 'Content-Type: application/json' -d '{"name":"Анна","email":"anna@example.com","amount":1}'
# 200 — корректный запрос (нужны тестовые реквизиты)
curl -i -X POST $BASE/.netlify/functions/create-payment -H "Origin: $BASE" -H 'Content-Type: application/json' -d '{"name":"Анна","email":"anna@example.com"}'
```

#### `GET /.netlify/functions/payment-status?orderId=<uuid>`

| Условие | Код | Тело |
|---|---|---|
| Метод не GET | 405 | `Метод не поддерживается.` |
| `orderId` не UUID (например `../x`) | 400 | `Некорректный идентификатор заказа.` |
| Заказа нет | 404 | `Заказ не найден.` |
| Есть | 200 | `{"status":"pending" \| "succeeded" \| "canceled" \| "failed"}` (внутренний `creating` отдаётся как `pending`) |

#### `POST /.netlify/functions/yookassa-webhook`

| Условие | Код | Тело |
|---|---|---|
| Метод не POST | 405 | `Метод не поддерживается.` |
| Не JSON / больше 4096 байт / битый | 400 | как в `create-payment` |
| Не объект | 400 | `Некорректное уведомление.` |
| `event` не `payment.succeeded`, `payment.canceled` или `payment.waiting_for_capture` | 200 | `{"received":true}`, ничего не меняется |
| `object.id` не строка или длиннее 128 символов | 400 | `Некорректное уведомление.` |
| Нет настроек ЮKassa | 503 | `Webhook временно недоступен.` |
| Не удалось получить платёж из API ЮKassa | 503 | `Не удалось проверить платёж.` (ЮKassa повторит уведомление) |
| В платеже нет `metadata.order_id` | 200 | `{"received":true}` |
| Не совпали `paymentId`, сумма, валюта `RUB` или `test: true` | 200 | `{"received":true}`, в логе «Уведомление ЮKassa не совпало…», статус не меняется |
| Совпало | 200 | `{"received":true}` |

Как меняется статус: `succeeded` ставится, только если в API `status=succeeded` и `paid=true`; `canceled` — если `status=canceled`; во всех остальных случаях запись не меняется. **Уже оплаченный заказ (`succeeded`) никогда не перезаписывается.**

Данные из тела уведомления (статус, сумма) не используются: функция берёт только `object.id` и запрашивает платёж у ЮKassa. Поэтому поддельное уведомление ничего не изменит. Проверка:

```sh
# Поддельный id → ЮKassa вернёт 404 → ответ 503, статус заказа не меняется
curl -i -X POST $BASE/.netlify/functions/yookassa-webhook -H 'Content-Type: application/json' \
  -d '{"event":"payment.succeeded","object":{"id":"fake-id"}}'
```

Сымитировать настоящее уведомление локально: создайте платёж, оплатите его тестовой картой, возьмите его `id` в кабинете тестового магазина ЮKassa и отправьте тот же запрос с этим `id`. Затем `payment-status` должен вернуть `succeeded`.

**Хранилище:** Netlify Blobs, store `yookassa-orders`, ключ — `orderId`, значение — `{ amountKopeks, createdAt, paymentId, status }`.

**Настройка ЮKassa** (кабинет тестового магазина): webhook `https://stvnislv.netlify.app/.netlify/functions/yookassa-webhook`, события `payment.succeeded`, `payment.canceled`, `payment.waiting_for_capture`.

**Навигация**
- [ ] Нижнее меню из четырёх кнопок. Повторное нажатие на активную кнопку прокручивает экран наверх.
- [ ] Свайп влево — следующий экран, вправо — предыдущий; на крайних экранах «резинка». Свайп не начинается с кнопки «Stvnislv» и у самых краёв экрана.

## 7. Как исправлять

### Где что менять

| Что | Где |
|---|---|
| Тексты, цены, контакты, работы сайта | Объект `site` в начале `<script>` в `index.html` |
| Тексты, цены, сроки, оффер Mini App | `tg-app/data.js` (`window.APP_DATA`). **Цены и услуги менять в обоих местах и в `brief.md`** |
| Положение щели на картинке | `SLIT` в `index.html` и в `tg-app/app.js` (числа одинаковые) |
| Свет и щель | CSS в `index.html`; слои перенесены в `tg-app/styles.css` один в один, менять в обоих местах |
| Портрет | Данные `PORTRAIT` встроены в `index.html` (сделаны из `portrait-cut.png`; `portrait.jpg` не используется) |
| Логика оплаты | `netlify/functions/_shared/payment.mjs` (валидация, настройки), `yookassa.mjs` (API), три обработчика рядом |
| Ответы бота | Объект `replies` в `bot/bot.mjs` |
| Описание и команды бота | Объект `BOT` в `scripts/setup-telegram-bot.mjs`, затем запустить скрипт. Лимиты: описание до 512 символов, короткое описание до 120 |
| Новый экран Mini App | `tg-app/CLAUDE.md`, абзац «Новый экран» |

### Порядок работы

1. Прочитайте нужный раздел `brief.md`. Если код с ним не совпадает, исправляйте код.
2. Внесите правку и прогоните `npm test`, если трогали `netlify/functions/`.
3. Проверьте вручную по чек-листу раздела 5: `index.html` открыть в Chrome, обе темы, ширина 320 px, режим без анимаций.
4. Коммит с коротким описанием по-русски.

### Git и публикация — важно

- **Не делайте `git push` без слова владельца «публикуй».** Каждый push в `main` запускает публикацию на Netlify и тратит 15 из 300 бесплатных кредитов в месяц. Когда кредиты кончаются, сайт отключается до следующего месяца.
- Если push нужен, но публикация не нужна (правка только документации), добавьте в сообщение коммита `[skip netlify]`.
- Force-push запрещён.
- Mini App выкладывается отдельно, вручную, тоже только по слову «публикуй». Команды — в `tg-app/CLAUDE.md`, раздел «Публикация и проверка». Выкладывать из копии папки, не из корня: иначе Netlify подхватит `netlify.toml` и функции оплаты.
- Что попадает на основной сайт (`netlify.toml`): `index.html`, `hero-bg.jpg` и `tg-app/` без `CLAUDE.md`. Исходники функций как файлы сайта не публикуются.

### Секреты

- Реальные ключи ЮKassa не использовать; только тестовый магазин.
- Токен бота и ключи держать только в `.env` локально и в переменных Netlify. Не коммитить и не вставлять в чаты, тикеты и скриншоты. Если токен бота утёк, в @BotFather выполнить `/revoke` и заменить строку в `.env`.
- Функции пишут в лог только HTTP-статус ошибки ЮKassa, без её текста и персональных данных. Сохраняйте это при правках: тест в `yookassa.test.mjs` проверяет, что текст ответа ЮKassa не попадает в ошибку.
